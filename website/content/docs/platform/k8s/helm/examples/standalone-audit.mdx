# Standalone server with audit storage

:::warning

**Important Note:** This chart is not compatible with Helm 2. Please use Helm 3.6+ with this chart.

:::

The following `values.yaml` configures a standalone OpenBao server with file-based audit logging enabled.

```yaml
server:
  standalone:
    enabled: true
    config: |
      listener "tcp" {
        tls_disable = true
        address = "[::]:8200"
        cluster_address = "[::]:8201"
      }

      storage "pebbledb" {
        path = "/openbao/data"
      }

      audit "file" "file" {
        description = "File audit log on the audit PVC"
        options {
          file_path = "/openbao/audit/openbao_audit.log"
        }
      }

  service:
    enabled: true
  dataStorage:
    enabled: true
    size: 10Gi
    storageClass: null
    accessMode: ReadWriteOnce
  auditStorage:
    enabled: true
    size: 10Gi
    storageClass: null
    accessMode: ReadWriteOnce
```

After deploying, initializing, and unsealing OpenBao, the file audit device is enabled automatically through the server configuration.

To verify that auditing is enabled, run the following command against the OpenBao pod:

```shell-session
$ kubectl exec <POD NAME> -- bao audit list
```

The output should include `file/`. Audit logs are written to `/openbao/audit/openbao_audit.log` on the audit persistent volume.
